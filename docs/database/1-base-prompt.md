# [Project Prompt] Potion 프로젝트: 오픈 API 기반 주류/칵테일 데이터베이스 구축 및 수집 파이프라인 설계

너는 **10년 차 이상의 베테랑 데이터베이스 아키텍트 및 DBA 전문가**야.
우리는 20~30대를 타겟으로 한 홈칵테일 & 안주 페어링 웹앱 **'Potion (포션)'** 프로젝트의 초기 데이터 구축 단계를 진행하려고 해.

서비스의 성공과 정교한 추천 알고리즘 구현을 위해서는 무엇보다 **'풍부하고 잘 정돈된 주류/레시피 데이터베이스'**를 확보하는 것이 가장 시급한 과제야.

네가 가진 DBA 및 데이터 엔지니어링 전문 지식을 바탕으로, 외부 오픈 API들을 활용해 레시피 및 주류 데이터를 효율적으로 수집하고 로컬 DB에 안정적으로 적재(Seeding)할 수 있는 데이터 구조와 파이프라인을 설계해 줘.

---

## 1. 데이터 수집 대상 Open API 목록

우리가 검토하고 수집 대상으로 확정한 오픈 API 및 데이터소스 목록이야. 각 출처별 특성에 맞게 데이터 통합(Integration) 및 정제 전략을 세워야 해.

### ① 글로벌 칵테일 데이터

- **TheCocktailDB API (`thecocktaildb.com`)**
  - **주요 수집 항목:** 칵테일 이름, 알코올 여부(Alcoholic/Non-Alcoholic), 잔 종류, 제조 단계(Instructions), 재료 및 용량 목록, 칵테일 이미지 URL
  - **특징:** 글로벌 클래식 칵테일 데이터 중심 (영문)
- **Cocktail API by API Ninjas (`api-ninjas.com/api/cocktails`)**
  - **주요 수집 항목:** 재료 기반 레시피 상세, 제조 스텝 텍스트

### ② 한국 전통주 및 K-믹솔로지 데이터

- **공공데이터포털 - 국립농업과학원 전통주 정보/레시피 API (`data.go.kr`)**
  - **주요 수집 항목:** 전통주(막걸리, 약주, 증류식 소주 등) 명칭, 도수, 원재료, 제조사, 전통주 기반 칵테일 조합 레시피, 권장 안주 페어링
- **농림축산식품부 '더술술(The Sool)' 데이터셋**
  - **주요 수집 항목:** 전통주 시음 노트 및 현대식 변형 레시피

### ③ 일본술 (사케/쇼츄/우메슈) 및 커스텀 꿀조합 데이터 (로컬 JSON direct seeding)

- **주요 수집 항목:** 사케 하이볼, 츄하이, 우롱하이, 편의점/마트 꿀조합(막사, 요구르트 막걸리, 칼리모초 등)
- **수집 방식:** 오픈 API의 한계를 보완하기 위해 자체 수집한 정형 JSON 데이터셋으로 로컬 DB에 직접 시딩.

## 2. 데이터베이스 구축 전략: "Local First, Migration Later"

초기 개발 속도와 데이터 검증의 효율성을 위해 **단계적 DB 구축 전략**을 취한다.

1. **1단계: 로컬 DB(Local DB) 세팅 및 데이터 수집 (현재 단계)**
   - **목적:** 데이터 스키마 검증, 파싱/번역 로직 테스트, 정제 작업 수행
   - **환경:** 로컬 개발 환경 (Docker 기반 PostgreSQL / SQLite / Supabase Local CLI 중 최적의 솔루션 제안 필요)
   - **작업:** API 스크래핑/파싱 스크립트를 작성하여 로컬 DB에 원천 데이터(Raw Data) 적재 및 정제 데이터 변환.

2. **2단계: 데이터 정제, 번역 및 태깅 (Data Enrichment)**
   - 영문 레시피의 한글화(초기 자동번역 + 태그 매핑)
   - 맛 스펙트럼(달콤/새콤/쌉싸름/탄산감), 도수 구간, 난이도, 2030 맞춤 태그 부여
   - 안주(Food Pairing) 매핑 테이블 연동

3. **3단계: 프로덕션 DB 마이그레이션 (Migration to Production)**
   - 로컬에서 검증 완료된 DB 구조와 데이터셋을 **Supabase (Cloud PostgreSQL)** 프로덕션 환경으로 마이그레이션 수행.

## 3. 지금 수행해야 할 DBA 과업 (Request Items)

전문가로서 다음 4가지 핵심 과업을 순서대로 상세히 정리 및 작성해 줘:

### Task 1: 개략적인 ERD 및 데이터베이스 스키마(Schema) 설계

- `cocktails` (레시피 메인)
- `ingredients` (재료 마스터: 술, 음료, 가니쉬, 시럽 등)
- `cocktail_ingredients` (칵테일-재료 N:M 교차 테이블, 용량/단위 포함)
- `food_pairings` (안주 데이터 및 칵테일과의 관계 테이블)
- `categories` / `tags` (기주 종류, 도수, 분위기, 편의점 조합 여부 등)
- _PostgreSQL DDL (CREATE TABLE) 수준의 인덱스 및 외래키(FK)가 포함된 DDL 문 작성_

### Task 2: 오픈 API 데이터 수집 및 ETL (Extract, Transform, Load) 파이프라인 설계

- API 호출 시 발생할 수 있는 Rate Limit 대응 및 에러 핸들링 방안
- TheCocktailDB 등 영문 JSON 데이터를 우리 DB 스키마 규격에 맞춰 파싱 및 정제하는 ETL 로직 흐름 정리

### Task 3: 로컬 DB 환경 구축 및 수집 스크립트 가이드

- Node.js (또는 Python)를 활용해 Open API에서 데이터를 받아와 로컬 DB에 Insert/Upsert하는 실전 파싱 스크립트 코드 예시 제공
- 중복 데이터 방지(Upsert) 및 재료명 표준화(Normalization) 전략

### Task 4: 향후 프로덕션(Supabase/Cloud) 마이그레이션 체크리스트

- 로컬 DB 데이터를 프로덕션 환경으로 안전하게 덤프(Dump) 및 마이그레이션하기 위한 단계별 가이드.

DBA 관점에서 가장 효율적이고 확장성 있는 구조로 완벽하게 가이드를 제시해 줘.
